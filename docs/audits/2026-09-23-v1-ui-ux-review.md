# Jianvia V1 UI/UX 审查与执行清单

审查日期：2026-09-23。基线：`codex/bazi-mvp` / `1855512`。本次只新增审查材料，未修改产品代码、配置、真实支付或线上部署。

## 结论

主要路径可以完成，窄屏没有普遍性横向溢出。当前最需要解决的是会话保留、问卷状态、弹窗行为和报告扫读层级，而不是整体换风格。页面已具备浅暖灰背景、统一无衬线字体、基本色彩和圆角变量，不能简单判定为“全站样式混乱”。但组件细节、导航权重和内容密度尚未形成稳定规范。

P0：本次覆盖范围内未发现普遍阻断主流程的问题。P1：会丢内容、误导选择、影响恢复或可访问性的缺陷，以及核心报告阅读效率问题。P2：密度、层级和一致性优化。下面成本是单名熟悉项目的工程师实施并做局部验证的估算；1 人日按 8 小时计算，不含真实支付、重新设计 AI 内容和实机采购。各项可能共用实现，不能机械相加。

## 运行与证据范围

- 实际启动现有 Next.js 项目于 `http://localhost:3100`，通过 Chromium 浏览器交互走流程，未修改页面 DOM 来制造截图。
- 视口为 375×844、390×844、430×844 CSS px，触控/移动模式。对应职业、城市、自定义三条完整路径；另外补走行业、合作关系完整路径。
- 报告使用项目现有 `REPORT_PROVIDER=sample`，支付使用 Mock；Supabase 凭据在本次审查进程中置空，不向生产数据库写入审查数据。测试数据为虚构出生信息。
- 检查了输入、未知时间、免费报告、反馈、五类方向、选择上限、补充说明、生成说明、等待、专项报告、展开、刷新和继续探索。
- 注入基础请求失败、支付请求失败、专项报告解析失败；这些用于验证 UI 恢复行为，不代表实际服务发生故障。成功重试已验证。
- 未调用 Gemini，所以不评估真实报告内容质量、真实等待时长；没有验证支付宝真实付款。
- 未用 iPhone/Android 真机。本次不能证明 iOS 日期选择器、中文输入法组合输入、软键盘、浏览器动态地址栏和安全区均已通过；这些列为后续验收项。
- 截图中的左下角 N 是 Next.js 开发工具，不属于线上产品，不列为设计缺陷。

## 建议执行顺序

1. 第一批：R01、Q01、Q02、Q03、Q04、D01，解决内容丢失、输入损坏、状态残留和回退；约2–3人日。
2. 第二批：F01、G01、W01、W03、Q05、G02，解决弹窗、错误恢复、等待可信度和可访问性；约2–3人日，弹窗共用实现只计算一次。
3. 第三批：R02、D02、E01、Q06、G03，集中优化报告扫描、导航和问卷密度；约2–3人日。
4. 其余P2文案和细节整合处理，约1–2人日；最后另留0.5–1人日做真机回归。整体约8–12人日，不含新增商业功能。
